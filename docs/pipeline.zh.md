# q-notes 编辑流程（中文版）

一个用来稳定产出中英双语笔记与文章的闭环系统：自动化负责所有重活，作者只提供唯一重要的东西——自己的观点。

> 本文是[`docs/pipeline.md`](./pipeline.md)（英文，权威版本）的中文对照。两者内容一致；如有冲突，以英文版为准。各阶段可直接运行的提示词在[`automations/`](../automations/)。旧的 `.codex/automations/` 提示词已被本流程取代，新的例程上线后应停用。

---

## 1. 为什么之前的设置什么都没产出

话题侦察（scout）本身是好的。它跑过两次（2026-05-28、2026-05-29），产出了 8 个研究充分的候选话题，然后系统就沉默了。失败是结构性的，不是质量问题：

| 失败 | 机制 |
|---|---|
| **开环** | 想法流进 `research/backlog.md`，但没有任何阶段有义务把它们取出来。每一项都还停在 `Status: Backlog`。 |
| **默认跳过的起草者** | 起草者被告知"没有草稿好过一份弱草稿"——于是每次运行最理性的行为都是跳过。叠加作者的完美主义，系统的默认产出就是零。 |
| **真实性缺口** | 草稿是从外部来源合成的。读起来像信息聚合，不像作者在思考——所以即使是好草稿也不觉得能发。 |
| **没有过期** | backlog 里的话题按定义是有时效的（"为什么现在有意思"），却永不过期，队列于是悄悄烂掉，而不是被迫做决定。 |
| **处处都要审核** | 连 backlog 的元数据更新都要走 PR，把人工审批点成倍放大。 |

下面每一个设计决定，都是为了补上其中一个缺口。

## 2. 设计原则

1. **作者是声音；AI 是其余一切。** 自动化负责侦察、核查、访谈、结构、编辑和翻译。每一篇发表作品里的观点都必须源自作者——通过一次 15 分钟的书面或语音"倾倒"廉价地捕获，绝不由模型编造。这是"聚合随机信息再发出去"的解药。
2. **流程永远产出它能产出的最小可发布物。** 任何阶段都不允许悄悄跳过。如果理想产出不可能，每个阶段都有明确的回退（见 §4.3 回退阶梯）。一篇短笔记胜过没有文章。
3. **每件产物都有一个时钟。** backlog 条目 21 天过期。草稿 PR 第 7 天降级、第 14 天关闭。"卡住"是系统会自己解决的状态；它绝不无限期地等作者觉得准备好了。
4. **分层的"完成定义"。** 完美主义靠一个隐含的"伟大文章"门槛存活。用每一层各自明确的清单替换它（§5）。清单通过，作品就发——改进放到发表之后，在 git 历史里做，像代码一样。
5. **一篇作品一个 PR，两种语言都在里面。** 一篇文章在英文版和中文版都存在之前不算完成。它们作为同一个编辑单元被审核、被发布。
6. **只有内容走 PR。** backlog、inbox、访谈和词表的改动直接提交到 `main`。人工审核只留给唯一需要它的东西：要发表的文字。
7. **声音靠机制来保证，不靠感觉。** `research/voice.md`（声纹）记录作者的立场、标志性措辞和禁用词。起草者把作者自己的一串原话作为"脊柱"带进每一篇，并声明任何无法追溯到作者输入的观点；发稿闸把声音问题标为问题，绝不作为拦截项。"容易"绝不能变成"泛泛"。（完整设计见 [`docs/companion-vision.md`](./companion-vision.md) §4。）

## 3. 内容层级

| 层级 | 标签 | 长度 | 门槛 | 目标节奏 |
|---|---|---|---|---|
| **笔记** | `note` | 300–700 词 | 一个想法、一个具体例子、一个被承认的反面观点。 | ≥ 2 / 月 |
| **文章** | `essay` | 800–1,500 词 | 现有 q-notes 门槛：可争论的论点、机制层面的论证、来源、反驳。 | ≥ 1 / 月 |
| **预测追踪** | `tracker` | 不限 | 回看某篇旧文里一个可证伪的预测，诚实打分。 | 有机会就做 |

一篇文章的 frontmatter 还带一个成熟度字段，让读者（和作者）知道"提前发"是有意为之：

- `maturity: seedling`（幼苗）——一个提前放出的想法，可能大幅改变。
- `maturity: growing`（生长中）——已论证、有来源，仍开放。
- `maturity: evergreen`（常青）——作者按现状为它背书。

发一篇 `seedling` 明确是成功，不是妥协。成熟度标签*就是*完美主义的泄压阀：它告诉读者他们拿到的是什么，从而让"暂时够好"成为一份诚实的契约，而不是降低了的标准。

## 4. 每周循环

作者总时间：**每周约 45–75 分钟**，分成两个自然的时段。其余全部自动化。

```
            ┌──────────────────────────────────────────────────────────┐
            │                                                          │
            ▼                                                          │
  周一  侦察 ──► backlog.md（≤3 个候选，强制过期）                       │
            │                                                          │
  周二  访谈者 ──► research/interviews/<date>-<slug>.md                 │
            │           + 通知作者                                      │
            ▼                                                          │
  周二–周四  作者倾倒（15–30 分钟，语音倾倒的质量，任何语言）
            │                                                          │
  周四  起草者 ──► 含英文+中文两版的 PR（或走回退阶梯）                   │
            │                                                          │
  周五  发稿闸 ──► 清单裁决 + 作者 5 分钟批准                            │
            │                                                          │
  每月  园丁 ──► 统计、过期、旧文挖掘 ─────────────────────────────────┘
```

### 4.1 周一 — 侦察（`automations/01-topic-scout.md`）

在现有侦察上的精修，有三处关键改动：

- **强制过期。** 在添加任何东西之前，把超过 21 天的条目标为 `Status: Expired (YYYY-MM-DD)`。强制衰减让队列保持诚实。
- **锚定到作者。** ≤3 个新候选里至少有一个要连到 `research/inbox.md` 里的一个想法，或连到某篇发表文章里的立场。侦察还做一次**反对狩猎**：找一个当下、聪明、且作者依据其公开立场大概率会*不同意*的观点——分歧是原创思考最可靠的发生器。
- **直接提交到 `main`。** backlog 元数据不走 PR。

### 4.2 周二 — 访谈者（`automations/02-interview-brief.md`）

把"AI 聚合"转化为"作者思考"的阶段。挑出单个最鲜活的候选（若某个 inbox 想法胜过整个 backlog，就用它），写一份访谈提纲到 `research/interviews/`，内含：

- 候选的论点与最强反驳，各用三句话；
- **五个尖锐的问题**，专门挖出只有作者能补的东西——经历、分歧、预测、利害（"你在哪里亲眼见过？""这个论点哪里是错的？""什么会让你改变主意？"）；
- 一个空白的 `## Author answers` 段落；
- 可选地，在某个问题下最多三条**作答方向**（`→ ` 开头的行）——作者可以采取的角度，在手机上渲染成"点一下就开头"的提示，绝不是替作者写好的答案。

作者用 15–30 分钟作答，任一语言，语音倾倒的质量——碎片、中英混排、错别字都没关系。先答几题、回头再补是预期之内的；**绿灯归作者所有**，作者满意时在手机上把提纲标为 `Ready to draft`。**答案是原材料；一份没有被标记为就绪的提纲最多产出一篇笔记，绝不产出一篇代笔的文章。**

### 4.3 周四 — 起草者（`automations/03-drafter.md`）

"默认跳过"规则被一个**回退阶梯**取代。起草者永远产出可得的最高一级：

1. **提纲被标为 `Status: Ready to draft`**（作者明确的绿灯）→ 起草一篇文章，其脊柱是作者自己的答案（他们的主张、例子、能用的措辞），以侦察的研究作为支撑证据。起草前重新校验来源。只有就绪的提纲才配得上完整文章的待遇。
2. **提纲有答案但没被标为就绪** → 作者还在处理它；不要在他们没签字的答案上写文章，也不要改动它的 `Status`。只有在没有更好的材料、或它临近过期时，才把它当作笔记的素材（软门）。优先让作者自己写完并标为就绪。
3. **没有可用答案，但 inbox 有一个有料的想法** → 起草一篇笔记，展开那个想法。
4. **都没有** → 起草一篇预测追踪更新，或一篇把某篇旧文连到此后发生之事的笔记。
5. **确实什么都没有** → 在访谈文件里提交一段一句话的运行报告，说明考虑过什么、为什么没有过关。沉默是被禁止的；一个可见的"为什么没有"本身就是流程还活着的信号。

作答方向（`→ ` 行）是访谈者的提示，不是作者的话：除非作者确实在 `## Author answers` 下写了内容，否则把该问题视为未作答。

起草者在**同一个 PR 里写两种语言版本**（见 §6），跑 `npm run build`，把 backlog 条目标为 `Drafted`，并开一个就绪（非草稿）PR，其正文包含：论点、层级、重新核对的来源、作者应该挑战的点、两种语言版本之间的主张一致性确认、一个**声音段落**（逐字保留的作者原话；任何无法追溯到作者输入的观点——这份清单应为空），以及**每种语言三个标题选项**，让作者在发布时不用写任何东西就能换标题。

### 4.4 周五 — 发稿闸（`automations/04-ship-gate.md`）

反完美主义的执行者。对每一个开着的内容 PR：

- 跑该层级的"完成定义"清单（§5）。若通过，评论一个裁决：**"可以发"**加三点摘要，让作者在手机上五分钟就能批准。
- 对着 `research/voice.md` 跑**声音检查**：命中禁用清单的，以及任何无法追溯到作者答案、想法或公开立场的带观点主张，都在裁决里标为问题（"写了 X——是你的意思吗？"）。声音标记塑造作者的那五分钟；它们绝不拦截一份通过的清单。
- 若 PR 已开 **> 7 天**：砍小它——把最强的单个想法抽成一篇笔记，重新分层，重新提出。系统把卡住的文章转成发出的笔记。
- 若开 **> 14 天**：关掉它，在 backlog 条目里记一行说明为何终止。终止是有效结果；僵尸不是。

作者仅有的两项周期性义务是周二的倾倒和周五的五分钟批准。两者都是手机大小的。

### 4.5 每月 — 园丁（`automations/05-gardener.md`）

每月一号：

- **吞吐报告**（提交到 `research/retro/YYYY-MM.md` 并作为通知发出）：按层级、按语言发表了多少；从草稿到发表的中位天数；过期/终止的数量；发表作品中源自作者想法或访谈答案 vs. 纯侦察发现的比例。
- **旧文挖掘**：重读作者发表过的文章，找出现在可以检验的预测（如咨询系列里"到 2027 年 EM 晋升率压缩"的检验），以及证实/证伪已发表论点的外部事件 → 提出预测追踪候选。这就是本站发展出*思想连续性*、而不是一串互不相关观点的方式。
- **声纹维护**：在 `research/voice.md` 的 `Proposed` 标题下提出 1–3 条新增——一个现已公开表达的立场、一个值得保留的标志性措辞、一个新的禁用词——从当月的访谈答案和发表作品里挖掘。只提出；晋升是作者的事，靠编辑那个文件。
- **卫生**：词表一致性检查、死链扫描、backlog 修剪。

## 5. 完成定义

一篇作品在其层级清单通过时发布——不是在它"感觉完成"时。

**笔记**
- [ ] 一个可争论、读者能一句话复述的主张。
- [ ] 一个具体例子或机制（不只是断言）。
- [ ] 一个被承认的反面观点，哪怕只有一句。
- [ ] 平实语言：没有聪明的非专业读者跟不上的行话或俏皮生造，也没有听起来聪明却不增添意义的措辞。刻意复用的关键词和词表术语是唯一例外，且在首次出现时定义。
- [ ] 可读的句子：没有又长又密、多从句的排比长句；默认一句一个想法，堆叠的从句、插入语或统计数字要拆成各自的句子。
- [ ] 人味声音：两种语言版本都跑过发前的人味检查（`research/human-voice.md` §4）——朗读测试、英文用缩写、克制转折/警句、段落节奏有变化、不复用开头/结尾框架、中文版不是英文的对齐翻译。
- [ ] 两种语言版本都在，且主张等价。
- [ ] 构建通过。

**文章** — 以上全部，另加：
- [ ] 以张力开场；论点在头两段内点明。
- [ ] 依赖当下事件的事实主张有链接来源，且在起草时重新校验。
- [ ] 最强的反驳被真诚对待，而不是稻草人。
- [ ] 至少包含一个可证伪的陈述或预测（预测追踪的燃料）。
- [ ] 推测被标注为推测。

**预测追踪** — 诚实给原预测打分（对 / 错 / 太早），链接原文，说明学到了什么。两种语言。这就是全部门槛。

明确**不在**任何清单上的：作者已重读五遍、每一段都打磨过、覆盖了所有角度。如果清单通过而作者仍犹豫，成熟度字段就降到 `seedling`，照发不误——说好的就是这个。

## 6. 双语设计（中英双语）

### 编辑契约

每一篇发表作品都有一个英文版和一个中文版，写成**转创（transcreation），而非直译**：

- **一致**：论点、结构/段落顺序、每一个事实主张、每一个数字、每一个来源链接、成熟度。
- **可调**：习语、句子节奏、修辞开场、以及标题（每个标题应在各自语言里有力，而不是对方的翻译）。
- **受词表约束**：复用的术语（如 "agent" → 智能体、"forward-deployed engineer"、"reward hacking"）用 `research/glossary.md` 里的译法，使本站长期读起来一致。起草者每次运行都把新定的术语追加进去。
- **方向**：先用作者访谈答案更偏向的那种语言起草，再转创到另一种。混合语言的答案是正常输入。
- **一致性检查**：起草者列出两版里的每一个主张，在 PR 正文里确认一致。发稿闸抽查。

### 内容模型（Phase 2 实现，独立 PR）

当前状态：语言是一个标签（`"English"`）；schema 没有语言概念。目标状态：

1. **Schema**（`src/content.config.ts`）：加 `lang: z.enum(['en', 'zh'])` 和 `translationKey: z.string()`（连接一对的共享 slug）。把现有文章上的 `"English"` 标签迁走。
2. **文件**：`src/content/posts/<translationKey>.en.md` 和 `<translationKey>.zh.md`。
3. **路由**：英文保留现有 URL（`/posts/<slug>`）；中文放在 `/zh/posts/<slug>`。每个文章页显示一个按 `translationKey` 解析的语言切换。首页/journal/标签页加语言过滤（默认英文，记住偏好）。
4. **订阅源**：`/rss.xml`（英）和 `/zh/rss.xml`（中）。
5. **排版**：在 `global.css` 里校验 CJK 渲染（字体栈回退到 `"Noto Sans SC"`/系统 CJK 字体；检查行高与标点悬挂）。
6. **回填**：三篇现有咨询文章补上中文版——给新流程三个现成的早期成果。

在 Phase 2 落地之前，写作流程仍不因站点工作而阻塞——但 zh 文件还不能放进 `src/content/posts/`，因为该集合会发布那里的每个文件、并从文件 id 构造 URL（一个 `slug.zh.md` 会以 `/posts/slug.zh` 出现在英文列表和 RSS 里）。所以 Phase 2 之前，起草者对英文保留当前的 `<slug>.md` 约定，把中文版停放在 `drafts/zh/<slug>.md`（在集合之外），放在同一个 PR 里。Phase 2 包含把停放的 zh 文件搬到位。

## 7. 捕获作者自己的想法

`research/inbox.md` 是一个无摩擦的捕获文件：一行一个想法，除了日期没有格式要求。捕获路径，摩擦从低到高：

- GitHub 手机 App → 直接编辑 `research/inbox.md`（30 秒）。
- 一个手机笔记/语音连接器（Apple Notes、Drafts，或某个消息连接器），配一个例程周期性把捕获同步进 inbox 文件。
- 对任意 Claude 会话说"加到我的 q-notes inbox：……"。

侦察和起草者把 inbox 想法当作**一等材料，排在外部发现之前**——一个半成形的、作者原创的想法，按政策胜过一个打磨过的聚合品。

inbox 有个姊妹：`research/voice.md`，即**声纹**。inbox 捕获作者*想什么*，声纹捕获他们*听起来怎样*——立场、标志性措辞、禁用词——好让起草者用作者的声音写，而不是让模型去想象一个声音。伴侣 App 的设计在 inbox 之上加了一个**想法回声**：陈旧、未消费的想法作为一键问题重新浮现（"还成立吗？"），一个"现在错了"的回答会把这个分歧作为新想法追加——作者和过去的自己争论，是系统拥有的最可靠的原创材料发生器。

## 8. 执行：接线这些例程

`automations/` 里每个文件都是一个自包含、工具无关的提示词：把它贴进一个定时的云端例程（Claude Code 云会话、Claude Desktop 自动化、一个调用 agent 的 GitHub Action，或任何能跑带仓库+网络访问的 agent 的调度器）。

| 例程 | 时间 | 需要网络 | 需要通知 | 写入 |
|---|---|---|---|---|
| 01 话题侦察 | 周一 08:00 | 是 | 否 | 提交到 `main` |
| 02 访谈提纲 | 周二 08:00 | 轻 | **是** | 提交到 `main` |
| 03 起草者 | 周四 08:00 | 是 | 否 | PR |
| 04 发稿闸 | 周五 08:00 | 否 | **是** | PR 评论 / 编辑 |
| 05 园丁 | 每月 1 号 09:00 | 轻 | 是 | 提交 + 通知 |

连接器需求：GitHub（全部）、网络搜索/浏览（侦察、起草者）、以及一个作者真会看的通知渠道——邮件或手机推送——给访谈者、发稿闸和园丁。一个日历连接器，每周挡出 30 分钟的"作者时间"（周二或周三），可选但推荐。

启动顺序：第一周先启用 01 + 02；第二周在有一份访谈拿到答案后加 03 + 04；第一个月之后加 05。旧的 `.codex` 例程已退休（见 `.codex/automations/RETIRED.md`）；在你的调度器里停用它们，只让 01–05 跑。并行跑第二个起草者，正是让未审核的文章上了站的原因。

### 硬闸：内容闸 CI

发稿闸（例程 04）是*编辑*审核，但它是一个提示词——可以被跳过。`.github/workflows/content-gate.yml` 是那个跳不过的*机械*闸：每个 PR 上它跑 `scripts/content-gate.mjs`（层级标签在、磁盘上双语成对含删除导致的落单、文章带来源链接，另加建议性的词数/破折号/长句警告）和一次完整的 `npm run build`。在 `main` 的分支保护里把它设为**必需状态检查**，这样任何内容 PR 在它通过前都无法合并。工作流在每个 PR 上都跑、没有 `paths` 过滤——一个被路径过滤的检查会一直 Pending，一旦设为必需就会拦住非内容 PR——而这个闸只审核一个 PR 改动的文章，所以非内容 PR 廉价通过、旧文章永不被重新审判。

## 9. 健康指标

园丁每月报告这些；任一目标连续三次未达标，意味着要修订的是流程设计（不是作者）：

| 指标 | 目标 |
|---|---|
| 每月发表篇数 | ≥ 3（任意层级组合），其中 ≥ 1 篇文章 |
| 草稿 PR → 发表的中位天数 | ≤ 7 |
| 两种语言都有的文章 | 100% |
| 扎根于作者输入（inbox 想法或访谈答案）的作品 | ≥ 60% |
| 超过 21 天的 backlog 条目 | 0（自动过期） |
| 什么都没产出（无产物、无报告）的起草者运行 | 0 |

第四个指标是把本站与一个聚合信息流区分开的那个。如果它下降，修法是更多访谈和旧文挖掘，不是更多侦察。
