# SemanticThoughtPackage

`SemanticThoughtPackage` is Q-notes' durable representation of a thought before, between, and beyond article runs.

It is deliberately separate from `EditorialRunManifest`:

```text
SemanticThoughtPackage = durable intellectual source
EditorialRunManifest    = execution state for one editorial run
```

A thought may exist without an article, survive multiple runtime/model versions, and compile into zero, one, or many artifacts. A run may reference a thought package, but runtime transcripts and prior generated prose are not the thought's source of truth.

## Canonical semantics

The package reuses `AuthorKernel` and `EditorialClaim` from `worker/editorial-run-manifest.ts`. It does not define a second ownership, evidence-role, inference-distance, language, or archive-provenance model.

This means load-bearing claims keep the same semantics already used by the editorial pipeline:

- ownership: `Q-explicit | Q-derived | External | Model-hypothesis`;
- source provenance;
- evidence role where applicable;
- inference distance and parent claims;
- EN/ZH language requirement;
- current/context-only/superseded/archived status where applicable.

`validateSemanticThoughtPackage()` delegates claim validation to the existing editorial-run validator, then checks thought-specific references and lifecycle data.

## What the package adds

A thought package can preserve state that should not be forced into an article:

- raw origins with stable refs and optional visibility labels;
- an unresolved question or current spine;
- uncertainties with stable IDs;
- load-bearing assumptions;
- alternative mechanisms without promoting them into author positions;
- evidence gaps and whether research or author input can resolve them;
- explicit author decisions;
- references to rejection and correction records;
- relations to other thoughts;
- compilation history recording which claims reached which later artifacts.

The package intentionally does not contain a model transcript or hidden reasoning trace.

## Persistence

New persisted packages live under:

```text
research/.companion/thoughts/<thoughtId>.json
```

`semanticThoughtRepoPath()` validates IDs before producing this path. The `.companion` location keeps runtime/editorial source artifacts out of public article rendering while retaining Git history, diffs, stable refs, and auditability.

The package must not contain secrets. `private` and `confidential` origin labels describe handling requirements; they are not a substitute for repository access controls or redaction.

## Capture remains lightweight

Do not create a full thought package for every raw spark.

A cheap inbox line can remain a cheap inbox line. Create or update a package when a spark is selected, linked, promoted, challenged, or otherwise needs durable semantic state. This keeps Capture low-friction while giving later Scout/Interviewer/Debugger/Drafter work stable IDs instead of copied summaries.

## Recompilation

`toSemanticThoughtCompilationInput()` produces a defensive-copy input containing the durable semantic material needed by a future runtime:

- origins;
- Author Kernel;
- claims;
- uncertainty;
- assumptions and alternatives;
- evidence gaps;
- rejection/correction refs.

It intentionally excludes prior compilation history, author-decision history, runtime IDs, and lifecycle status. Those records remain auditable on the source package, but they do not silently become evidence for a new model run.

To compare runtimes/models, pin the package file to a Git commit/blob SHA and pass the same compilation input to each configuration. Compare semantic outcomes such as form choice, ownership preservation, unsupported extensions, preserved uncertainty, evidence gaps, and author questions. Exact prose equivalence is not required.

## Example lifecycle

```text
inbox spark
  -> promoted to T17
  -> assumptions/evidence gaps added
  -> author leaves one inference unresolved
  -> run A compiles C1 into a Note
  -> later evidence updates T17
  -> run B re-evaluates the same durable thought
```

The package records both compilations, but a later run starts from the current semantic source rather than from the prose generated by run A.

## Boundaries

This contract does not:

- migrate every historical article or spark;
- create a knowledge-graph UI;
- replace positions, rejection records, article lifecycle, or `EditorialRunManifest`;
- make stored model hypotheses author-owned;
- create a new database;
- require drafting or publication as an end state.
