# Positions

Model-produced hypotheses the author has explicitly adopted (`docs/pipeline.md` §10). This
file answers "what has Q adopted", not "how does Q sound" — that split is deliberate, so
`research/voice.md` doesn't absorb a second job. Nothing here is a style rule.

Consumers: the **drafter** reads this as author-owned material for the Author Kernel — an
adopted entry is `Q-explicit`, on the same footing as an interview answer; the **ship gate**
appends an entry the moment the author replies `**Adopt hypothesis — Hn**` on a PR; the
**gardener** proposes promoting an entry into `research/voice.md ## Stances` once it has
actually been taken in public in a published piece.

Rules:

- Automations only ever *append* here, and only on an explicit `**Adopt hypothesis**`
  comment — never on a candidate hypothesis alone. A rejected or never-decided hypothesis is
  never recorded anywhere.
- The author may edit or delete any entry, anytime; this file commits directly to `main`
  like `research/voice.md`.
- One line per entry: date, `(adopted hypothesis, PR #N)`, the claim as adopted.
